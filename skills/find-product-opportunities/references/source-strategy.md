# 数据源策略与回退

## 选择顺序

1. 优先一手来源：官方功能、定价、文档、公开 changelog、原始社区讨论和原始数据页。
2. 搜索引擎、目录和聚合站用于发现来源，不把摘要当最终证据。
3. 公开源足以完成基础研究；登录浏览器、用户导出和付费工具只在现成可用时增强。
4. 每个 finalist 至少覆盖三类独立信号，并主动寻找反证。

## 信号家族

- **搜索与趋势**：Google Trends、搜索建议、相关搜索、问题型查询、类别趋势。用于方向和语言，不用于精确量级。
- **社区痛点**：Reddit、论坛、公开 issue、评论、专业社区。记录用户任务、频率、成本和 workaround。
- **商业证明**：竞品定价、付费计划、服务报价、采购页面、付费目录。寻找真实付费动作而非只有流量。
- **竞品缺口**：官方功能/定价、评论中反复出现的限制、目标用户错配、集成或工作流缺口。
- **分发可达性**：有明确搜索意图的页面、垂直社区、生态市场、集成目录、可合作渠道。
- **技术变化**：官方 API、模型/硬件成本、平台能力、法规变化。技术变化只能解释“为什么现在”，不能替代需求。

## Google Trends

Google Trends 是可选方向性信号。它的新版/经典版 URL、页面结构、对比数量和内部接口都可能变化或限流：

- 不依赖第三方网页拼接的 Trends URL；
- 不假设一次可以比较八个词；需要对比时按平台允许规模分批，并用锚点词保持相对可比；
- 页面不接受查询参数、接口返回 429 或图表不可读时，停止重试，改用搜索建议、相关查询、公开趋势报道、社区时间序列或其他方向性来源；
- 在报告中记录缺口，不把“无法访问”解释为“没有需求”。

## 失败回退

| 失败 | 回退 |
|---|---|
| Trends 页面/接口变化 | 搜索建议、相关搜索、社区时间分布、其他趋势源 |
| 社区需要登录 | 公开 issue、公开评论、搜索索引到的原帖、同类社区 |
| 付费 SEO 数据不可用 | 公开 SERP/页面与趋势信号；明确不提供量级结论 |
| 单一来源冲突 | 保留冲突，增加另一类独立来源，降低置信度 |
| 候选证据稀疏 | 淘汰或输出 NO-GO，不降低 finalist 门槛 |
| 短时限流 | 停止密集请求，切换来源；不要绕过风控 |

## 停止条件

标准深度在以下条件满足时停止：已经发散 20–40 个候选、初筛 8–12 个、最终候选满足证据门槛，并且继续采集不会改变排序或置信度。若证据始终不足，直接进入 NO-GO 报告。
